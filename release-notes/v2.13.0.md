# Snacks v2.13.0

**Automated Media Library Transcoder**

Cluster file transfers to remote workers exposed through **Pangolin** (HTTPS reverse proxy on a VPS) now use an automatic WAN profile: smaller upload/download chunks (25 MB cap), exponential retry backoff, and faster failure hand-off to job reassignment. Workers reached over **Tailscale** (`100.64.0.0/10`) or the local LAN keep the existing transfer behaviour — no new settings required.

---

## WAN transfer profile (Pangolin)

- **`ClusterNetworkHelper`** — classifies nodes as WAN when `IpAddress` is a public routable address or a hostname (manual `cluster.json` URL such as `https://encode.example.com:6767`) that resolves only to public IPs. Tailscale CGNAT, RFC1918, loopback, and link-local ranges stay on the LAN profile.
- **`TransferProfile` / `ClusterFileTransferService`** — WAN uploads and downloads cap effective chunk size at `min(ChunkSizeMB, 25 MB)` so reverse proxies only need to accept one chunk per request; retries use 5 → 10 → 20 → 40 → 60 s backoff with at most five session failures before the master reassigns via the existing dispatch fallback. LAN/Tailscale paths are unchanged (user `ChunkSizeMB`, 5 s fixed upload retry, higher failure budget).
- **`ClusterService`** — passes WAN detection into dispatch, recovery upload, and output download.

### Pangolin proxy notes (operator)

If transfers stall behind Pangolin, ensure the proxy allows request bodies of at least **30 MB** and read/send timeouts long enough for one chunk at your slowest expected uplink. Set `UseHttps: true` in `cluster.json` for manual worker URLs.
